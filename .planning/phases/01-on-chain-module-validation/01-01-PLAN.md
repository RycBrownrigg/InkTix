<objective>
Close the Wave-0 tooling gap and land the first end-to-end on-chain validation of the
InkTix contract, then expand it along the core dependency chain.

This plan is tracer-first. Task 2 is the tracer: one thin path wired through every
layer this phase will ever touch — Cargo feature gate → crate test tree → `ink_e2e`
harness → live `ink-node` over `CONTRACTS_NODE_URL` → `instantiate` → owner-gated
message call → nested-`Result` unwrap → state read-back. Proving that path end-to-end
before eight more tests are written against it is the point: if a sibling test module
cannot reach the macro-generated `InkTixRef`, or the feature gate leaks e2e tests into
the default `cargo test` run, we find out after one commit rather than after eleven.

Task 1 precedes the tracer because it is a *tooling* prerequisite explicitly flagged as
a Wave 0 gap in RESEARCH.md (the dev-node launcher does not resolve the binary that is
already on disk), not an architectural layer of the system under test.

Purpose: VALIDATE-01 requires each contract module to be exercised against a live
`ink-node`. Today zero on-chain tests exist — the 14 inline unit tests are off-chain
only (CONCERNS.md). D-01 locks the harness to automated `#[ink_e2e::test]` Rust tests
so Phase 2 can re-run a representative subset against Passet Hub.

Output: a working `ink_e2e` harness under `contracts/inktix/src/tests/e2e/`, the first
three modules of the Phase 1d dependency chain validated on-chain, and a `dev-node.sh`
that resolves its binary reliably.

<assumption_delta_decision>
## Assumption Delta: one validation surface becomes two

**Transition detected (singular → plural).** Before this phase the project had exactly
one validation surface: off-chain `#[ink::test]` functions, all of them inline in
`contracts/inktix/src/lib.rs` inside `mod inktix { mod tests }`, with a mostly-empty
`crate::tests` module holding helper structs. This phase adds a second, parallel
surface: on-chain `#[ink_e2e::test]` functions running against a live chain.

**Q1 — does the current primary identity still name the right thing?**
Yes. `tests` remains the correct root name for "the crate's tests"; the new tier is a
*child* (`tests::e2e`), not a peer that invalidates the parent's name. No rename.

**Q2 — promote the general case, or add alongside?**
**Add alongside. Do NOT promote.** Promoting would mean restructuring into
`tests::unit` + `tests::e2e` and relocating the 14 inline `#[ink::test]` functions out
of `lib.rs`. Rejected: those 14 tests are the VALIDATE-02 green baseline, and moving
them in the same phase that introduces a new tier destroys the ability to attribute any
regression to the right cause. `tests::e2e` as a feature-gated child is the minimal
correct expression of the plural case, and it keeps VALIDATE-02/VALIDATE-03 true by
construction (the gate is what stops the two tiers from merging).

**Q3 — second source of truth for pass/fail?**
Yes, and it is ranked, not tied. The **test suite is primary** (machine-executed);
`docs/v2_plan.md`'s Phase 1d checklist (D-03) is a **derived human record, never
authoritative**. Plan 01-03's prohibition enforces that ranking: no checklist row may
be marked passing without an actually-executed run that reported a pass.
</assumption_delta_decision>

  <action>
The script currently hardcodes `BIN_PATH="$NODE_DIR/ink-node"` (i.e.
`.tooling/ink-node/ink-node`) and gates installation on `[ ! -x "$BIN_PATH" ]`. On this
machine the extracted binary actually sits one level deeper, at
`.tooling/ink-node/ink-node-mac/ink-node` (288MB, executable, present since Nov 2025),
so the guard evaluates true and the script re-downloads the ~300MB release asset on
every run. The mac-universal asset nests its payload one directory deeper than
`--strip-components=1` accounts for; the Linux assets may nest differently.

Replace the fixed-depth assumption with layout-independent resolution rather than
guessing a per-platform `--strip-components` count:

1. Add a `resolve_bin()` helper that searches `$NODE_DIR` for the executable:
   `find "$NODE_DIR" -type f -name ink-node 2>/dev/null | head -n 1`. Use `-type f` so
   the `$NODE_DIR` directory itself (also named `ink-node`) can never match.
2. Change `BIN_PATH` from a fixed assignment into a value assigned from `resolve_bin()`
   at startup. Keep `NODE_DIR` and `TOOLING_DIR` as they are.
3. Gate installation on the resolved value: download only when `resolve_bin()` returns
   empty or the returned path is not executable. After `install_ink_node()` runs,
   re-resolve, and if resolution still yields nothing, print an error naming `$NODE_DIR`
   to stderr and `exit 1` — never fall through to `exec` on an empty path.
4. Move the `chmod +x` and the macOS `xattr -dr com.apple.quarantine` calls so they
   operate on the *resolved* path, not on the old fixed `$NODE_DIR/ink-node`.
5. Add a `--resolve-only` first-argument mode: when `$1` is `--resolve-only`, resolve
   (without ever downloading), print exactly one line of the form
   `ink-node binary: <absolute path>` on stdout, and `exit 0`; if nothing resolves,
   print an error to stderr and `exit 1`. This flag must be consumed so it is never
   forwarded into the `exec "$BIN_PATH" --dev --tmp "$@"` argument list.

Keep `set -euo pipefail`, the pinned `INK_NODE_VERSION="v0.47.0"`, `detect_asset()`,
and the existing `exec "$BIN_PATH" --dev --tmp "$@"` launch line otherwise unchanged.
Note in a comment above `resolve_bin()` that the fixed-depth extraction path was wrong
for the mac-universal asset (RESEARCH.md Pitfall 3).
  </action>
